# Lifetime

独立的演员制作与演出预览工具。只有 Actors 和 Play，沿用原 Lifetime 的浅色三栏界面。

## 启动

需要 Node.js 22.12+ 或 24+。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5190。资源服务自动运行在 5191。

```sh
npm test
npm run build
npm start
```

构建后，`npm start` 在 http://127.0.0.1:5191 同时提供页面和资源接口。不需要 WorldForge、Voxel Studio 或其他兄弟项目。

## 使用

- **Actors**：左上角展开演员切换器，新建演员；生成模型后，进入动画制作，生成并播放动画。模型重新生成后形成新版本，已有动画保留原版本绑定。支持暂停、停止、进度拖动和循环。
- **动作制作**：左侧动作库新建动作。点击地图标点的 ＋ 创建 p1、p2，拖到预览地面定位（也可点击“放置”后点击地面）；离地高度大于 0 即为空间点。将点拖进文本框、点击“插入”或输入 @ 引用，然后输入要求、生成、预览并保存。直接使用当前模型的动画库，无需动画池。程序控制接口见 [运动接口文档](docs/motion-api.md)。
- **已有素材制作动作**：Actors 的动作制作中展开“用已有动画创建基础动作（本地）”，选择路线移动、前往表演并返回或原地表演，选择已有动画并保存。动画步骤属于演员层；模板无需 chat。
- **Play**：导入并打开地图，加入演员，设置实例的位置、朝向与缩放。放置地图 P 点，从演员层动作库加入完整动作，把动作的 p1、p2 等输入绑定到实际地图点。预览或直接播放时本地计算 NavMesh；不在 Play 编辑动画。保存演出可恢复配置。源动作修改后需“更新动作引用”。旧演出可播放，点击“将旧动作归入演员库”后再编辑绑定。详情见 [地图动作接口](docs/scene-motion.md)。
- **角色状态机**：一个状态执行一个完整动作。例如“绕池塘跑步”与“跑到桥中央、面向池塘、跳舞后空翻并返回”是两个状态。设置执行次数、等待与后续状态，即可循环切换；选择自身可持续重复。中央播放控制所选角色，“播放全部角色”启动所有启用角色。切换保留真实站位，规则随演出保存，整个流程本地运行。详情见 [状态机接口](docs/character-machine.md)。
- 导入独立渲染方案时，先打开目标地图；会保存为新的地图资源，不覆盖旧地图。含外部资源引用的地图应从原 WorldForge 导出完整场景 ZIP。缺少模型或 HDRI 的包会明确报错。
- 地图导出为可重新导入的 `.lifetime-scene.zip`，包含地图、渲染方案及嵌入的 HDRI；演员实例另存于演出草稿。
- 工作区切换保留当前数据与任务，只让活动工作区持续渲染。保存失败可重试保存已有生成结果；取消请求只是停止等待，后端任务可能继续执行。

生成接口通过浏览器直接访问后端。需要更换地址时，复制 `.env.example` 为 `.env`，设置 `VITE_GENERATION_API` 后重启开发服务；发布构建需重新 build。该变量不是密钥存储位置。

运行数据位于本项目 `data/actors`、`data/maps`、`data/performances`，不提交 Git。当前任务状态和未保存草稿保存在浏览器内存中；刷新前应完成保存。

地图动作当前支持静态地面寻路、完整到达和已有动画组合；不包含地图生成/编辑、Stage、独立长动画生成、环境互动、动态避让、物理/IK 或 NPC agent。动作规划器只生成结构化计划，运动执行器不逐帧调用 AI。当前动画播放器处理骨骼姿态，不提供粒子/VFX 动画制作；不支持的数据明确报错。
