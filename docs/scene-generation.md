# 场景自动生成

第三步的自然语言入口覆盖素材准备与地图装配：选择地图 → 输入要求 → 指导文档 → 复用／生成模型与动画 → 本地 P 点和 NavMesh → 演员完整动作 → 角色状态机 → 保存新演出。已有演出可按要求增量修改，未涉及实例保持原样。NPC 播放期间不调用 AI。

## 数据与职责

- `shared/sceneBlueprint.ts`：指导文档声明角色模型、动画素材需求和行为意图。模型与动画选择 `existing` 或 `generate`，动作引用逻辑动画 key。未知地图特征、非法步骤、错模型动画引用在提交生成之前拒绝。
- `shared/sceneBuild.ts`：持久任务记录，保存提交时的地图版本、基础演出、要求、指导文档、任务状态和结果引用；不复制地图几何或模型内容。
- `AssetManifest`：逻辑角色／动画 key 到真实 actorId、modelRevisionId、clipId 的映射。素材就绪后确定性解析为已有 `ScenePlan`，无需再次调用 chat。
- `server/builds/planner.ts`：一次 `/api/chat` 读取地图语义摘要、素材目录和上次行为意图。完整几何、模型节点、逐帧动画及坐标不进入规划上下文。
- `server/builds/service.ts`：调度、校验、入库与恢复。新模型先生成并保存，其动画才进入队列；不同模型最多并发 2 项，动画最多 3 项，总计最多 4 项。每条动画绑定提交时的真实模型版本，换造型后不能沿用旧模型的动画。
- `generation/client.ts`：Actors 手动生成和本地服务共用的后端传输；模型 SSE／JSON、动画 JSON，保留完整响应，禁止隐式生成重试。
- `client/scene/generationCoordinator.ts`：观察任务，素材就绪后领取装配会话，复用本地位置解析、动作编译及演出装配。完整新演出最后发布，失败不覆盖原演出。

## 播放语义

移动速度和动画播放倍率独立；地面路径由 NavMesh 计算，动画生成描述只要求角色姿态／原地循环。移动动画必须确实返回 `loop=true`，不修改后端循环字段以绕过校验。

单次表演可使用可循环素材：“翻三个跟头”被解析为三个有限 `playClip` 步骤，每步播放一次。保留素材原始 loop 元数据与时长。状态引用完整行为，例如巡游 → 桥上表演并返回 → 巡游，不能把每个动画当作独立状态。

自动 P 点可继续在角色位置编辑中调整。实际站位、路线、原地动作空间和状态衔接均在本地预检；台阶能力不足时显示原因和调整入口，不自动提高能力强行通过。当前不支持飞行导航、椅子接触求解、动态避让、物理／IK 或环境改动。

## 存储与恢复

`data/builds/<id>.json` 原子保存任务，`result_<taskId>.json` 暂存收到但尚未保存的完整结果；资源成功入库后删除对应结果缓存。模型和动画使用固定资源 ID，重复保存不会制造新版本。任务记录保留逻辑描述和资源引用。

- 刷新或关闭页面：本地服务继续已提交素材任务；重新打开地图后恢复显示，必要时点击继续装配，不重新规划／生成。
- 停止后续任务：不提交排队中的生成；已发送任务继续接收并保存，不声称远端已取消。
- 保存失败：重用收到的结果，仅重试保存。
- 远端连接中断／服务重启：没有可靠远端任务查询或幂等契约，未收到结果的项标为“结果待确认”，整组继续不自动重发；用户可明确重试该项，可能产生一次新生成。
- 浏览器装配中断：服务端空间草稿保存各角色的点位、完整动作、问题与验证检查点；浏览器缓存不作为发布依据。已完成的素材保持入库，成功的本地步骤按输入签名复用。独占会话有效期 5 分钟，活动页面每 30 秒续租；过期可恢复，另一个页面不能同时装配。
- 地图更新：拒绝继续发布旧地图版本的演出，已生成素材保留。规划失败、空间失败、素材失败分别显示，不丢弃成功项。

空间装配需要打开 Lifetime 页面；关闭浏览器后可以生成素材，但不会在后台独立计算地图导航和发布演出。

## 程序端口

本地资源服务提供以下 JSON 接口，Vite 在开发时转发 `/api/builds`：

| 请求                              | 输入／用途                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------ |
| GET `/api/builds?mapId=…`         | 按地图查询构建记录，最新在前                                                                     |
| GET `/api/builds/:id`             | 获取真实状态，不重新提交                                                                         |
| POST `/api/builds`                | `{id,request,base,climb,blueprint?}`；固定 id 去重，base 为基础演出；省略 blueprint 则调用规划器 |
| POST `/api/builds/:id/retry`      | `{taskId?}`；指定项重试，省略则继续队列／装配准备，不重发失败或未知项                            |
| POST `/api/builds/:id/cancel`     | 停止后续任务                                                                                     |
| POST `/api/builds/:id/claim`      | `{owner,climb?}`；领取／续租装配会话                                                             |
| POST `/api/builds/:id/release`    | `{token,error?}`；释放会话、保留素材等待继续                                                     |
| POST `/api/builds/:id/checkpoint` | `{token,expectedRevision,draft}`；原子保存空间草稿，版本冲突时拒绝覆盖                           |
| POST `/api/builds/:id/complete`   | `{token,performance}`；校验地图版本、指导文档与未涉及角色后保存演出                              |

`window.lifetimeSceneBuilder.buildBlueprint(blueprint, request?)` 复用素材生成与装配链路，跳过 chat；`getBuildState()` 返回当前构建记录。旧 `build(scenePlan, request?)` 继续支持已有资源的结构化装配，不生成素材。具体端口参数以 `play/workspace.ts` 导出的类型为准。

## UI 与配置

场景右侧只有文本要求、生成／修改、必要时停止或继续，以及结果播放。生成中按角色展示模型和动画的名称、描述及真实阶段／错误；不伪造百分比。素材保存后可在中央查看模型、预览动画并返回地图。完成的任务详情收起，仍可展开检查；生成素材自动进入演员库。

后端契约快照为 [api-reference-2026-10-15.md](api-reference-2026-10-15.md)。`.env` 中 `VITE_GENERATION_API` 同时作为浏览器与本地生成的默认地址；服务可用 `LIFETIME_GENERATION_API` 单独覆盖，重启后生效。自动生成模型使用 GPT／VOXEL，动画默认 GPT／QUICK；只有明确指定才使用 PRO，指导文档省略动画 mode 时补为 quick。已提交任务保留原模式，不改写已生成资源。当前不提供更多引擎配置 UI。

多人要求必须展开为多个角色条目，可以引用相同演员资源，但各自拥有实例、状态机和位置意图。本地装配共享角色体积站位预留表；相同“门口”不会直接成为相同坐标。空间不足保留检查点供人工调整，详见 [角色碰撞与站位](character-collision.md)。单次指导文档仍最多8个角色，演出最多100个实例，超过单次上限应明确提示，可分次追加，不能悄悄减少人数。

回归使用隔离目录和固定后端响应；真实模型／动画生成验证与固定样本验证分别记录于 [verification.md](verification.md)。通过协议和播放验证不等于所有生成动作都具备高质量接触效果，生成质量仍受实际后端结果影响。

## 空间失败后的继续制作（2026-10-15）

区域搜索升级见 [地图语义与本地区域求解](spatial-resolution.md)：摘要增加源资源别名、九宫格及容量限制；本地搜索 NavMesh 区域候选，引导线联合选点，绕水路线检查实际水岸及全水域环绕。检查点、人工覆盖与发布规则保持一致。

场景要求下的“构建记录”可以切换本地图的历史尝试，后一次规划失败不会隐藏前一次已生成的模型／动画。所有素材卡仍可预览，生成资源也可在演员库查找。

素材就绪后，“检查地图并调整”仅执行本地选点、NavMesh、动作与状态衔接检查，不调用 chat 或素材生成。已有空间草稿用“查看并调整空间草稿”打开：左侧选择本次构建的角色，右侧查看地点、动作和具体问题；中央显示 P 点及所选动作的实际导航路线，无法连通的路段不会画成可走直线。

拖动点位或点击点名后在地图表面放置，修改可保存或取消；路线可追加路径点。保存调整不发布演出；“重新检查”先保存修改，再复用原模型／动画、未变的完整动作与检查结果。手动位置被锁定，不被自动候选覆盖。全部检查通过后才出现“完成并发布”，保存演员动作与新演出，原演出保持不变。工作区切换保留尚未保存的调整，地图切换前须保存或取消。

引导线在有限局部范围搜索同一支撑层的可走点，保留有效转折；执行时仍采用严格的 NavMesh 点位与连续路线校验。建筑 center 查询从低处支撑面寻找可站立的内部位置，不直接取包围盒顶部；能站但无法进入时保留候选点与错误，供手动修复。不自动提高台阶、跨越水面或用亭外点替代中央要求。此能力是有限候选查询与本地验证，不等于任意地图均能自动理解或生成连通道路。

装配草稿与地图版本及指导文档绑定；每次检查点按预期 revision 和独占会话写入，保存失败立即停止，不声称已落盘。发布须匹配最后检查通过的实例、点位、动作绑定与状态配置。规划器的原始文本在校验前保留（上限20万字符），无效输出只作为诊断记录，不直接执行。
