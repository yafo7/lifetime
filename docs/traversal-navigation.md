# 跨高度导航

## 使用

修改路径时，P 点可以放到可站立的台阶或桥面。预览只计算路线；播放优先复用同模型版本的跳跃动画，没有才提交后端生成，并显示导航动画任务。素材保存在 Actors，后续地图和动作继续复用。

鸟等需要飞行的角色，在 NPC 设置的“移动能力”选择“行走、跳跃与飞行”，保存修改。地面 P 点仍先走路，悬空 P 点使用飞行。需要先跑再飞时，安排一个地面途经点，再接空中点。开启飞行代表用户明确赋予该实例飞行能力，不按演员名称猜测。

## 本地路径与动作适配

- `TraversalPlanner` 先使用原 NavMesh。台阶能力、角色尺寸和坡度不变，支持连续地面的桥坡仍正常行走。
- 地面不连通时，在有限邻域按 NavMesh 连通分区均衡采样，建立临时图，连接步行边与有界跳跃边。候选图最多约150节点，最多200次跳跃轨迹检查。选择路线后，每段地面路径重新用真实 NavMesh 计算。
- 跳跃要求两端有可站立多边形，以64段抛物线采样检查角色半径和高度。默认最大上升高度为 `clamp(height × 1.5, 1.5, 4)`，水平距离为 `clamp(height × 3, 3, 8)`，单位是地图世界单位；可由 `sceneMotion.traversal.jumpHeight/jumpDistance` 显式设置，契约分别限制在0.2–10、0.2–20。
- 飞行只对 `traversal.fly=true` 开启。先试直达，再有限尝试升高、绕开起降点的折线路径；检查沿途身体空间、地图边界和高度。目标在实体内部、路径受封闭结构阻挡或搜索预算内无解时，明确报错，不穿墙或传送。
- `TriangleIndex` 对地图原始三角形建立 CPU 空间索引，`TraversalClearance` 进行静态圆柱包络的射线扫掠。索引由地图几何快照弱持有，不依赖渲染批处理；不是精确物理或完整三维全局寻路，不保证找到所有理论可达路线。
- `adaptTraversal` 只生成执行计划，不修改演员源动作、状态机、地图 P 点或已保存动画步骤。原移动动画用于地面段，跳跃段播放一个完整跳跃周期并由路径拥有根高度；飞行段循环飞行动画至到达。停顿表演继续使用原素材，执行器继续支持暂停、停止和拖动进度。
- 路径修改、空间草稿预检及场景装配共用本地路线能力。自动地点仍优先选择真实可站立表面；AI 不负责逐帧移动，也不凭空生成世界坐标。空间预检可以先确认几何路线，实际播放前补齐所需导航动画。

## 动画任务与恢复

`POST /api/builds/traversal` 接收场景快照、实例 ID 和 `jump/fly` 需求，不调用 chat、不生成模型、不发布新演出。任务使用现有模型依赖队列、原子日志和结果缓存，记录 `purpose=navigation-assets`；普通场景历史不混入素材任务。界面通过专用任务摘要显示状态。

生成请求使用 GPT / QUICK、当前模型原始 JSON。跳跃提示要求原地起跳落地、不循环，飞行要求原地循环。后端返回的真实时长和完整结果保留；位移由本地路线承担。复用及生成都严格绑定模型版本，其他版本的同名动画不复用。

刷新只恢复和观察；同一需求去重。服务重启后的未知远端结果不会自动重发，显示“确认重新生成”；保存失败缓存结果并提供“继续保存”。停止角色或切换工作区不会丢弃已提交任务，结果仍入库；过期播放准备不能把角色放回已关闭的场景。

## 验证

- `tests/traversal.test.ts`：抬高平台上下跳跃、地面优先、悬空点、飞行绕墙、障碍内部、低顶棚、版本绑定和执行落点。
- `tests/sceneMotionPort.test.ts`：预检不生成、播放补齐一次、真实执行器抵达、后续复用。
- `tests/sceneGeneration.test.ts`：无 chat/模型请求、任务去重、精确入库版本、保存失败只重存。
- 只读庭院验证：现有钢铁侠鸭尺寸、climb=0.3，从池塘外围跑至起跳点，跳到桥的独立导航分区，再沿桥抵达原桥中央 P 点；不修改正式数据。
- 浏览器固定样本：预检、跳跃生成与播放、开启飞行并抵达空中点、保存刷新与复用。生成响应为固定样本，未调用付费生成；实时后端契约于2026-10-15核对，见 api-reference-2026-10-15.md。
