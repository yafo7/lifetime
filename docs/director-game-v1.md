# 导演驱动的交互剧情：第一版设计

日期：2026-10-14。本文是实施设计，新增能力尚未实现；不代表六章《最后一名嫌疑人》已进入制作。

## 1. 第一版目标

用户给出一段故事或灵感，导演将其组织成一个小型可玩开场：准备必要角色与动画，装配 NPC 动作和状态机，编写初始对话。玩家进入地图，靠近 NPC 按 E 交谈，在关键节点选择选项；选择改变剧情进度和 NPC 行为。导演随后依据已经发生的事情，编写有限的下一段。

最小闭环：

```text
用户灵感 + 已选地图
  → 导演生成开场方案
  → 复用／生成素材，装配动作、状态机与对话
  → 玩家进入地图，NPC 自主活动
  → 靠近按 E，交谈并选择
  → 记录选择，切换 NPC 行为
  → 到达续写节点，导演补下一小段
  → 玩家再次交谈，看到不同的故事和行动
```

“自主活动”在本版指 NPC 按配置巡游、停留和切换行为。“导演 agent”在本版指通过现有 chat 接口读取上下文、输出结构化方案并调用受限制作端口的协调器；不需要新增 agent 框架。

## 2. 现有基础与新增范围

| 能力 | 当前基础 | 本版工作 |
| --- | --- | --- |
| 模型／动画与版本 | Actors、共用生成客户端、持久素材队列 | 复用；导演声明最小素材需求 |
| 动作与空间装配 | 完整动作、地图语义索引、本地选点、静态 NavMesh | 复用；校验剧情要求可执行 |
| NPC 日常活动 | 次数、等待、后续状态；暂停、继续、切换状态端口 | 增加交谈期间的临时控制与剧情事件连接 |
| 玩家进入地图 | 第三人称、WASD、跳跃、进入／退出 | 增加 E 交互和可配置玩家素材引用 |
| 对话与选项 | 尚无 | 新增最小对话图与 UI |
| 剧情推进 | 尚无 | 新增小型剧情事实、事件、会话进度 |
| 导演 | 已有场景指导文档规划与生成装配 | 扩展开场规划和有限续写 |

现有玩家入口使用指定装甲鸭资源；它适合验证交互，但不等于已支持导演生成的侦探主角。将玩家模型及移动动画改成可配置引用属于本版接入工作。原始动画结果仍完整保存，玩家控制位置与姿态采样继续分开。

本版使用已导入且可通行的地图。岛屿或庄园外观取决于所选地图；地图不匹配时明确说明，不生成地图、不把园林假称为岛屿。不加入完整证据板、自由输入聊天、语音、AI 运镜、环境物体操作、动态避让、GOAP 或完整六章案件。

## 3. 职责和数据边界

同一仓库、同一应用，先在 Play 内增加“剧情试玩”，保留 Actors／Play 两个工作区。制作与游玩共用现有资源和执行端口。

| 层 | 职责 |
| --- | --- |
| 导演 | 将灵感组织为局部故事、素材需求、行为和对话；续写下一段 |
| 角色剧情配置 | 角色设定、已知信息、状态对应的对话入口、选项和行为变化 |
| 剧情运行层 | 判断对话条件、提交选择、维护共同事实、派发角色事件 |
| 动作／状态机 | 执行已有完整动作，暂停、恢复、从当前站位切换 |
| 玩家交互层 | 移动、接近提示、E、选项 UI、进入／退出 |

角色携带自己的故事，但源演员仍是可复用素材。具体故事身份、对话和剧情状态归场景角色实例；多个实例可引用同一个演员，互不串写剧情。共同事实属于该次故事，不能只藏在某个角色状态机里。

拟定的最小数据分为以下几类，实施时再落具体字段与版本校验：

- **故事约束**：用户明确设定、导演已采用的补充、尚未确定的问题、当次规划范围。
- **开场包**：角色素材与行为指导、角色剧情配置、初始对话、玩家配置、续写节点，引用最终保存的演出和资源版本。
- **角色剧情配置**：角色 key／实例 ID、设定与已知信息、对话入口条件、选项效果与状态引用。对话可随剧情阶段变化，不能只按“正在走路”决定所有台词。
- **游玩会话**：开场包版本、已发生事件、玩家选择、有限剧情事实、已解锁对话、续写结果及请求状态。

剧情会话与演出设计配置分别保存。运行中走到了哪里、做了哪个选择，不修改源演员和设计站位。跨刷新保存玩家与 NPC 的实际站位、剧情事实和当前逻辑状态；恢复时本地重新寻路，不保存 NavMesh、派生路线或逐帧时钟。

角色的活动状态、剧情事实、正在交谈的临时状态分开：例如“已接受委托”是剧情事实，“门厅巡游”是活动状态，“正在交谈”是临时交互。无需为每句台词增加一个运动状态。

## 4. 导演的工作边界

导演需要详细到能执行，但每次只编写当前可玩的片段和近期后续：

1. 保留用户明确的设定，不替玩家做选择；补充开场所需细节时记录来源为导演补充。
2. 开场只写一个场景目标、少量角色、一段交谈和一个关键选择，不一次确定完整案件与最终结局。
3. 用户给定和已经呈现的事实保持一致；未呈现的草案可以调整。角色只根据自己的已知信息说话，不自动共享所有幕后信息。
4. 重大未定事实保持未定。用户只给葬礼灵感时，可以留下死因疑点，不立即指定凶手或诅咒真相。
5. 输出引用可校验的结构化数据，不输出任意代码、坐标或接口地址。坐标和路线由本地解析。
6. 只为当前开场声明必要素材；初次方案允许使用已有队列生成。续写默认限于已准备的角色、动作和地点，不在每次交谈后生成素材。
7. 首版每次关键交谈给 2–3 个选项；每个选项明确记录结果，并定义可观察的对话或行为后果。
8. 空间不支持或资源不满足时报告原因，保留可用结果，不能用无关动作假装完成需求。

这些约束进入规划提示和本地校验。结构校验只能保证引用与操作合法；事实一致性还需固定样例、续写上下文和内容审核验证，不能宣称 JSON 校验即可保证剧情质量。

## 5. 六步实施

每步完成一个可验收结果后再进入下一步。先用固定内容验证执行，再接 AI 制作和续写。

### 第一步：固定小样与最小数据契约

**交付**：一个手工编写的开场包和共享校验，使用临时样本与已有素材。

- 地图：一张已导入且路线可达的地图。
- 玩家：侦探身份；交互验证阶段可以使用现有模型占位，并明确标注。
- NPC：小女儿，沿短路线走动、停留。
- 开场：葬礼之后，小女儿询问侦探是否愿意帮忙。
- 选项 A：“带我去看看。”——接受邀请，NPC 前往指定地点等待。
- 选项 B：“先说说发生了什么。”——先了解情况，NPC 留在原处，解锁另一段说明。

门厅／书房只是地图存在相应地点时的叙事名称；示例不预设实际地图具备室内空间。两种选择都提供继续交谈的入口，不让玩家无事可做。

先定义对话节点、选项、有限条件和效果（记录事实、解锁对话、切换已有状态、请求续写）。动作和状态必须来自同一角色的实际绑定，跨角色、失效版本和未知引用拒绝提交。

**验收**：样本经过严格校验；缺少节点／角色／状态时可明确定位错误；旧演员和演出仍能原样打开。

### 第二步：靠近 NPC 按 E 交谈

**交付**：第三人称游玩中的交谈界面。

复用现有玩家输入和世界位置，按可配置距离、相近高度及静态遮挡筛选交谈对象；多个对象按距离和稳定 ID 确定唯一目标。显示“E 与某某交谈”，离开范围后隐藏。只接受一次按键触发，避免长按反复打开。

交谈时禁用玩家移动并清空按键，暂停所选 NPC 的活动，必要时朝向玩家；其他 NPC 继续运行。退出交谈后恢复控制；没有选择效果则恢复原行为，有效果则交给第三步切换。NPC 原本已暂停时，不擅自启动。Esc 优先关闭对话，再按才退出游玩。

面向玩家需要使用真实当前站位的临时目标或姿态控制，不改写保存的地图 P 点；运动执行器仍不依赖 DOM 或网络。

**验收**：走近、按 E、阅读、关闭后继续活动；远距离、隔墙、长按、失焦、换工作区和退出均正确；不会传送 NPC 或恢复失效异步动作。

### 第三步：选项驱动剧情和 NPC 状态

**交付**：无需 AI 的两条可玩分支和局部剧情运行层。

选项先完成引用、条件和空间能力检查，再记录事实并派发角色事件，调用现有状态切换端口。分支返回的行为可能是“继续原活动”或“从当前站位进入新行为”，不能一律恢复交谈前状态。

每次选择只提交一次。切换动作失败时显示原因并保留可恢复结果，不重复应用选择，也不声称 NPC 已到达；剧情的“已接受邀请”与“已到达目的地”由不同事件确认。新行为可以在动作完成后解锁下一次交谈。

先采用明确的事件到状态映射，不把完整条件语言塞入运动状态机，也不引入每个 NPC 自由规划。角色故事配置与状态机通过相同角色 key／实例 ID 和事件关联。

**验收**：两条分支的后续对话和行为可观察地不同；重开对话不重复委托；行动完成后解锁后续；中断、不可达与两个实例同时运行互不串写。

### 第四步：导演从灵感制作开场

**交付**：输入短灵感，生成可试玩的开场包。

导演读取用户输入、实际地图摘要、素材目录和受支持能力，输出三份互相关联的指导：素材需求、NPC 活动、对话剧情。默认一个玩家、一个主要 NPC、一个关键选择；额外角色只有当前片段确实需要时才加入。

规划先校验逻辑引用和支持能力，再复用现有 `SceneBlueprint`、素材队列及本地装配。逻辑角色 key 解析为真实实例，动作、状态、对话、玩家素材绑定到已保存资源。主角素材也复用演员库与模型依赖队列，不再固定为装甲鸭。

完整开场包就绪后才开放“进入剧情”。现有普通场景生成入口继续可用；剧情构建增加自己的关联记录，不将普通演出误当作已完成的游戏。生成或装配失败保留素材与方案，继续时不重新规划或重复提交未知请求。

**验收**：一个短灵感产生必要角色、可执行活动和有效对话；玩家进入后完成第三步分支；刷新构建页面可恢复；完整链路先以固定后端响应验证，再单独进行有授权的真实生成验证。

### 第五步：根据选择有限续写

**交付**：玩家选择后，导演能补出不同的下一段，而不只是读取预先写完的分支。

选择的即时事实与动作效果由已有方案本地执行。到达预设续写节点后，导演接收用户约束、已确认事实、该角色可知信息、已提交选择、当前逻辑状态和可用动作，输出下一段短对话、2–3 个选项及事件效果。

续写只能追加当前故事允许的内容，不删除玩家选择、不改写已经发生的事实、不重建整个演出。可切换到预先装配的行为；新角色、素材、地图变化和新复杂动作留给后续版本。自由文字输入也留到下一版。

同一节点与选择组合使用稳定请求 ID，结果保存后才应用；每次只允许一个续写请求。响应需要匹配故事版本、会话版本和事件序号；退出、换图、加载另一存档后的旧结果不能写入新会话。失败时保留已提交选择和现有活动，提供明确重试，不自动重复未知结果的请求。

续写内容未就绪时不展示虚构后续；NPC 可以继续已经批准的等待／日常活动。对话中显示必要的准备状态，不暴露内部协议和配置。

**验收**：相同开场的两种选择分别送入真实不同的上下文，产生不同下一段；固定响应覆盖正确追加、非法效果拒绝、网络失败、响应过期和重复点击；另做真实 chat 试玩以检查内容一致性，结构通过不能代替内容验收。

### 第六步：存档、集成和第一版验收

**交付**：一条可保存、可重新打开的端到端试玩。

故事包保存制作结果，游玩会话保存玩家进度、事件和续写结果。存档关联明确的包／演出／资源版本；新开游戏创建新会话，不覆盖上一轮选择。刷新读取已保存内容，不重新生成开场或已完成续写。临时地图点、派生路径与播放时钟不持久化。

恢复到最近完整交互检查点：重新检查当前站位可达性，再启动逻辑行为；对话中断重新打开当前节点，已提交选项不重新执行。切换工作区冻结游玩，回到该故事继续或明确重进；退出游玩后恢复编辑模式，释放输入、对话订阅与临时角色。

**验收**：固定样本两条分支各走通至少两次交谈；选择→行动→动作完成→下一段对话可见；保存刷新后进度一致；继续、重开和换工作区不串会话。回归既有演员、普通演出和生成恢复功能。

## 6. 代码落点建议

沿用 TypeScript、DOM、Three.js 和现有 chat／生成客户端，只在实施相应步骤时创建所需文件，不预建空目录。

| 位置 | 预计职责 |
| --- | --- |
| `src/shared/` | 对话、故事包、角色剧情配置、会话与效果协议及校验 |
| `src/client/play/` | E 交互、对话面板、试玩入口和玩家配置接入 |
| `src/client/scene/` | 局部剧情运行、导演方案与角色实例的装配 |
| `src/client/services/sceneMotionPort.ts` | 复用暂停／恢复／切换；必要的交谈临时控制 |
| `src/client/motion/` | 仅必要的执行支持，保持无 DOM／网络／LLM |
| `src/server/` | 导演规划、续写请求与会话存储；复用现有构建队列 |
| `data/` | 本地故事包和游玩会话，细分目录在实施时确定，不提交 Git |
| `tests/` | 对话效果、行为连接、续写恢复及隔离浏览器固定样本 |

不绕过业务端口直接操作渲染对象；E 提示所需的实际实例位置通过 Viewport／运动端口的窄接口读取。业务不进入地图渲染内部；NPC 配置不引用玩家 UI，剧情效果不调用跨仓库代码。

## 7. 第一版完成标准

完成六步才称为导演驱动的交互剧情第一版。前三步完成的是手工内容交互原型，第四步完成的是 AI 开场制作，第五步补齐随玩家选择继续编写的核心能力，第六步保证可保存和稳定重玩。

- 用户输入短灵感，系统在所选真实地图中准备一个小开场。
- 一个可操作玩家、一个自主活动 NPC、一个关键选择，不要求完整案件。
- 按 E 交谈，选择改变故事事实、后续对话和至少一种 NPC 行为。
- 至少一次关键节点触发导演续写，已有事实与玩家选择被保留。
- 构建、游玩和续写失败有可恢复状态，刷新不重发未知生成请求。
- 固定后端回归与隔离浏览器流程通过；实现变更后运行相关测试、`npm test` 和 `npm run build`。
- 实际模型、动画生成及真实 chat 内容试玩另行记录，不能用模拟验证宣称生成质量已达标。

现有能力细节参见 [scene-generation.md](scene-generation.md)、[character-machine.md](character-machine.md)、[player-controls.md](player-controls.md) 和 [architecture.md](architecture.md)。本文本轮只新增设计文档，内容与差异检查即可，不运行无关构建。
